## Шаг 2: Анатомия компонента и ментальный сдвиг «Класс vs Функция» (1.5 часа)
На Шаге 2 мы планируем работать со статичной структурой шаблона и стандартной интерполяцией строк через двойные фигурные скобки `{{ }}` (пока без Control Flow).

В React компонент — это функция, которая при изменении стейта вызывается сверху вниз целиком. В Angular компонент — это класс (декларативная фабрика). Ваша задача на этом шаге — понять структуру декоратора `@Component`.
1. Откройте `src/app/app.component.ts`. Обратите внимание на метаданные декоратора:
	• `standalone: true` — компонент независим и сам управляет своими зависимостями (как полноценный изолированный модуль).
	• `imports: [...]` — массив, куда вы будете явно импортировать другие компоненты, директивы или встроенные фичи (никакой глобальной магии, полная прозрачность для сборщика).
2. Проведите мысленный мост: декоратор `@Component` — это конфигурация сборки и рантайма, а сам класс — это место, где вы описываете свойства и методы, которые отработают ровно один раз при инициализации, настроят связи, а дальше уйдут в тень, уступив место графу реактивности.

Мы создадим экспериментальный компонент, который наглядно покажет анатомию Standalone-подхода в Angular 20+ и позволит провести тот самый лабораторный эксперимент по «убийству ререндеров» из вашего подкаста.
Для чистоты эксперимента мы намеренно объявим в классе обычное классическое свойство (не Сигнал), чтобы вы увидели, как ведет себя рантайм Zoneless-приложения при попытке мутировать данные напрямую, и почему класс в Angular — это просто фабрика, отрабатывающая один раз при старте.

### 2. Код экспериментального компонента
Откройте файл `src/app/components/day-1/step-2/step-2.ts` и приведите его к следующему виду. Код снабжен подробными комментариями, проводящими ментальные мосты с React:

```ts
import { Component } from '@angular/core';

@Component({
  selector: 'exp-day-1-step-2',
  // 1. Полная независимость. Компонент сам является модулем (как файлы в React/Next.js)
  standalone: true, 
  // 2. Явный импорт зависимостей. Здесь нет авто-магии, всё что нужно шаблону — импортируем сюда
  imports: [], 
  // Inline-шаблон (как JSX в React), чтобы не прыгать по файлам во время опыта
  template: `
    <div style="padding: 20px; border: 2px dashed #666; font-family: monospace;">
      <h3>🅰️ Экспериментальный стенд: Шаг 2</h3>
      
      <!-- Данные из класса рендерятся напрямую в текстовые ноды живого DOM -->
      <p>Обычный счётчик (не Сигнал): <strong>{{ counter }}</strong></p>
      <p>Результат тяжёлого вычисления: <strong>{{ runHeavyCalculation() }}</strong></p>
      
      <div style="margin-top: 15px;">
        <button (click)="incrementCounter()">1. Мутировать counter напрямую</button>
        <button (click)="forceTriggerDetection()" style="margin-left: 10px;">2. Триггернуть проверку</button>
      </div>
      
      <p style="color: #666; font-size: 12px; margin-top: 15px;">
        *🔬 Откройте Console в DevTools, чтобы увидеть рантайм-логи.
      </p>
    </div>
  `,
  styles: []
})
export class Step2 {
  // Локальный стейт компонента (обычное свойство класса)
  counter = 0;

  constructor() {
    // Вызовется ровно ОДИН раз за всю жизнь компонента
    console.log('🏗️ [Constructor] Angular: Фабрика компонента инициализирована!');
  }

  /**
   * Тяжёлая функция (аналог функции без useMemo в React)
   */
  runHeavyCalculation(): string {
    console.log('🔴 [Heavy Calc] Выполняю тяжёлые вычисления в теле класса...');
    return 'Результат #42';
  }

  /**
   * Клик по первой кнопке
   */
  incrementCounter() {
    this.counter++;
    console.log(`⚡ [Click] counter изменен напрямую. Текущее значение в классе: ${this.counter}`);
    console.log('🤔 Проверьте UI: изменилась ли цифра на экране? (Спойлер: в Zoneless-режиме — нет!)');
  }

  /**
   * Клик по второй кнопке (эмуляция forceUpdate / жесткого триггера)
   */
  forceTriggerDetection() {
    console.log('🔮 [Force Update] Пытаемся заставить Angular проверить дерево...');
    // В Zoneless приложении без использования Сигналов этот метод просто отработает, 
    // но Angular не пойдет перечитывать класс, потому что граф зависимостей пуст!
  }
}
```

### Что покажет этот лабораторный опыт в браузере?

Когда вы откроете страницу и нажмете на первую кнопку:
1. Вы увидите в консоли, что метод constructor и метод `runHeavyCalculation` отработали строго один раз при первой загрузке страницы.
2. При клике на кнопку «Мутировать counter напрямую» переменная в памяти класса будет увеличиваться (1, 2, 3...), но интерфейс останется неподвижным.
3. Самое главное: функция `runHeavyCalculation` НЕ вызывается повторно при кликах!

**Вы наглядно убедились:** в Zoneless Angular обычные свойства класса мертвы для шаблона. Чтобы заставить UI реагировать, нам нужен реактивный примитив.

## Шаг 3: Освоение встроенного Control Flow (2 часа)
**Что планируем:** Освоение встроенного Control Flow, который вы уже предварительно наметили в глобальном плане. В JSX вы привыкли писать логику ветвления и циклов прямо на JavaScript (`{condition && <Component />}`, `{items.map(item => ...)}`). В Angular 20+ для этого используется нативный декларативный макросинтаксис компилятора с префиксом `@`.

В JSX вы использовали JS-код: тернарные операторы `? :`, логическое `&&` и метод `.map()`. В современном Angular для этого есть встроенный декларативный макросинтаксис компилятора. Он не создает Virtual DOM, а генерирует прямые инструкции для живых нод.

Чтобы сгенерировать компонент с вашими точными требованиями с помощью Angular CLI, используйте следующие флаги:
• `--selector="exp-day-1-step-4"` — принудительно задает кастомное имя тега.
• `--standalone` — гарантирует standalone-режим (в Angular 20+ он включен по умолчанию, но флаг явно фиксирует это).
• `--inline-template` (или `-t`) — встраивает HTML-шаблон прямо в `.ts` файл (отменяет `.html`).
• `--inline-style` (или `-s`) — встраивает CSS-стили прямо в `.ts` файл (отменяет `.css`).
• `--skip-tests` — отменяет генерацию файла тестов (`.spec.ts`).

_Создаем компонент с нужными настройками:_
```bash
yarn ng generate component components/day-1/step-3 --selector="exp-day-1-step-3" --standalone --inline-template --inline-style --skip-tests
```

В Zoneless-режиме Angular ленив. Чтобы Control Flow наглядно реагировал на изменения, нам понадобится сделать один шаг вперед и импортировать примитив `signal`. Сигнал — это реактивный узел, который сам скажет компилятору, в какое именно место шаблона `@if` или `@for` нужно доставить новые данные.

Код компонента `src/app/components/day-1/step-3/step-3.ts`:
```ts
import { Component, signal } from '@angular/core';

interface ProcessItem {
  id: number;
  name: string;
}

@Component({
  selector: 'exp-day-1-step-3',
  standalone: true,
  imports: [], // Встроенный Control Flow (@if, @for) не требует импорта сторонних директив!
  template: `
    <div style="padding: 20px; border: 2px dashed #666; font-family: monospace; margin-top: 20px;">
      <h3>🅰️ Экспериментальный стенд: Шаг 3 (Control Flow)</h3>

      <div style="margin-bottom: 15px;">
        <button (click)="toggleLoader()">Переключить лоадер</button>
        <button (click)="addProcess()" style="margin-left: 10px;">Добавить процесс</button>
        <button (click)="clearProcesses()" style="margin-left: 10px;">Очистить все</button>
      </div>

      <div style="background: #222; color: #0f0; padding: 15px; border-radius: 4px;">
        <!-- 1. Ветвление через @if / @else -->
        @if (isLoading()) {
          <div class="spinner">⏳ [Рантайм]: Сканирование графа зависимостей...</div>
        } @else {
          <div>
            <h4>📋 Активные процессы в песочнице:</h4>

            <ul>
              <!-- 2. Цикл через @for с обязательным трекингом по уникальному ID -->
              <!-- Дополнительно берем контекстные переменные компилятора: $index и $even -->
              @for (item of processes(); track item.id; let idx = $index, isEven = $even) {
                <li [style.color]="isEven ? '#0f0' : '#00bc8c'">
                  [{{ idx }}] ID: {{ item.id }} — Поток: {{ item.name }}
                </li>
              } @empty {
                <!-- 3. Блок @empty автоматически отрендерится, если массив пуст -->
                <li style="color: #ff3333;">📭 [Empty State]: Данные полностью отсутствуют</li>
              }
            </ul>
          </div>
        }
      </div>
    </div>
  `,
})
export class Step3 {
  // Инициализируем реактивные атомы данных (Сигналы)
  isLoading = signal(false);
  processes = signal<ProcessItem[]>([
    { id: 101, name: 'Main-Reactor-Core' },
    { id: 102, name: 'Zoneless-Change-Detector' }
  ]);

  private nextId = 103;

  toggleLoader() {
    // Инвертируем булево значение внутри сигнала
    this.isLoading.update(v => !v);
  }

  addProcess() {
    // В Angular 20+ мутировать массив напрямую нельзя, иммутабельно обновляем сигнал процессов
    this.processes.update(items => [
      ...items,
      { id: this.nextId++, name: `Sub-Routine-${Math.random().toString(36).substring(7)}` }
    ]);
  }

  clearProcesses() {
    this.processes.set([]);
  }
}
```

> [!info] **Критически важный инсайт для Senior React разработчика на этом шаге:**
> Обратите внимание на выражение `track item.id`. В отличие от React, где пропущенный `key` выдаст лишь предупреждение в консоли браузера, компилятор Angular выдаст ошибку сборки, защищая граф обновлений от неоптимальных рендеров по дизайну.

### Подводные камни и архитектурные инсайты Control Flow для Senior React Разработчика

Когда вы пощелкаете кнопками в браузере, обратите внимание на три фундаментальных отличия от JSX:
1. **Отсутствие «Ререндера всей функции»:** Когда вы нажимаете Добавить процесс, Angular не перерисовывает весь блок `@else`. Он не делает diff всего дерева UI. Благодаря тому, что `processes()` — это сигнал, компилятор при сборке превратил блок `@for` в микро-функцию, которая слушает этот сигнал и хирургически вставляет в DOM только одну новую строчку `<li>`, вообще не трогая предыдущие элементы.
2. **Жесткий контракт `track` на уровне компиляции:** В React вы могли забыть написать `key={item.id}` в `.map()`, и приложение продолжило бы работать, выплюнув предупреждение в консоль. В Angular 20+ синтаксис `@for` (`item of items; track item.id`) делает `track` строго обязательным. Попытка пропустить `track` приведет к ошибке компиляции (`NG8131`). Фреймворк на уровне дизайна защищает вас от неоптимальных перерисовок списков.
3. **Контекстные переменные `$index`, `$even`, `$odd`, `$first`, `$last`:** Встроенный движок компилятора Angular автоматически рассчитывает эти переменные внутри тела цикла `@for`. Вам больше не нужно вычислять индексы или проверять остаток от деления на 2 в уме, чтобы подкрасить четные строки таблицы.
4. **Связка `@for + @empty`:** В JSX для отображения "пустого экрана" вам приходилось писать тернарный оператор вокруг маппинга: `items.length === 0 ? <Empty /> : items.map(...)`. В Angular блок `@empty` интегрирован прямо в синтаксис цикла, что делает разметку чистой и читаемой.

1. Компонент — это не функция, это фабрика. Он выполняет свой код (конструктор) ровно один раз при монтировании, настраивает декларативные связи и больше никогда не перечитывается рантаймом сверху вниз.
2. Прощай, Virtual DOM Диффинг. Angular компилирует декларативный Control Flow (`@if`, `@for`) в прямые, точечные JS-инструкции для конкретных текстовых нод живого DOM.
3. Реактивность без костылей. Граф зависимостей Сигналов собирается автоматически. Вам больше не нужно вручную следить за массивами зависимостей хуков или бояться, что случайный клик уронит перформанс вашего приложения.
Поздравляю с успешным завершением Дня 1! Песочница полностью настроена и работает в Zoneless-режиме на Yarn.
