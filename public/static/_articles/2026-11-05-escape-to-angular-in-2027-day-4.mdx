# 🅰️ День 4

## Теоретическая подготовка: Ментальный сдвиг

| Концепт | Как это в React (`react-router-dom`) | Как это в Angular 20+ (`@angular/router`) |
| :--- | :--- | :--- |
| **Параметры URL** | Хуки `useParams()`, `useSearchParams()`. | Свойства-сигналы через декоратор `@Input()` или DI-сервис `ActivatedRoute`. |
| **Защита роутов** | Компоненты-обертки (`<ProtectedRoute><Outlet /></ProtectedRoute>`). | **Functional Guards:** Чистые функции, внедряемые в конфигурацию роута через DI. |
| **Предзагрузка** | Метод `loader` в Data Routers (запускается параллельно с рендером). | **Resolvers:** Функции-трансформеры, которые не пустят компонент на экран, пока данные не разрешатся. |

## Шаг 1: Функциональный роутинг, Lazy Loading и Component Input Binding (3 часа)
- Теория: Изучение декларативной конфигурации роутера (`provideRouter`). Разбор флага withComponentInputBinding(), который автоматически превращает query-параметры (`?search=apple`) и dynamic params (`/user/:id`) в стандартные нативные сигнальные инпуты компонента (`input()`), полностью избавляя от ручного парсинга URL.
- Практика: Создание ленивого модуля для админ-панели лаборатории (`loadComponent: () => import(...)`). Настройка сквозного прокидывания параметров URL напрямую в стейт без участия хуков.

```bash
yarn ng generate component components/day-4/step-1 --selector="exp-day-4-step-1" --standalone --inline-template --inline-style --skip-tests
```

### 1. Настройка маршрутов

`src/app/app.routes.ts`

```ts
import { Routes } from '@angular/router';

export const appRoutes: Routes = [
  {
    path: '',
    pathMatch: 'full',
    loadComponent: () => import('./components/main-layout/main-layout').then(m => m.MainLayoutComponent)
  },
  {
    path: 'dashboard',
    loadComponent: () => import('./components/dashboard-layout/dashboard-layout').then(m => m.DashboardLayoutComponent)
  },
  {
    path: 'dashboard/:id',
    loadComponent: () => import('./components/dashboard-layout/dashboard-layout').then(m => m.DashboardLayoutComponent)
  }
];
```

### 2. Глобальная конфигурация роутера

Чтобы магия автоматического связывания URL с Сигналами заработала, нужно зарегистрировать маршруты с флагом `withComponentInputBinding()`

```ts
// src/app/app.config.ts

import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { appRoutes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    // Глобальный перехватчик ошибок браузера
    provideBrowserGlobalErrorListeners(),
    // Активируем роутер со сквозным пробросом параметров URL в инпуты
    provideRouter(appRoutes, withComponentInputBinding())
  ]
};

```

### 3. Ленивый standalone-компонент

Фреймворк сам заполнит `id` и `search` реактивными данными при изменении URL. Обрати внимание, как computed-модель моментально реагирует на изменение пропсов, избавляя тебя от `useEffect`

```ts
// src/app/components/day-4/step-1/step-1.ts

import { Component, input, computed, effect } from '@angular/core';

@Component({
  selector: 'exp-day-4-step-1',
  standalone: true,
  imports: [],
  template: `
    <div class="lab-sandbox dark stack1">
      <h3>🅰 День 4: Шаг 1 — Функциональный роутинг & Component Input Binding</h3>

      <div class="lab-monitor stack1">
        <h4>📡 Монитор параметров навигации URL:</h4>
        <!-- Сигнальные инпуты автоматически извлекают данные из URL рантаймом -->
        <p>Динамический ID процесса (из пути): <strong>{{ id() ?? 'Не указан (/dashboard/:id)' }}</strong></p>
        <p>Поисковый фильтр (из query parameters): <strong>{{ search() ?? 'Отсутствует (?search=...)' }}</strong></p>
      </div>

      <div class="lab-monitor stack1">
        <h4>📊 Вычисляемые метрики (Computed DAG):</h4>
        <p>Текущее состояние графа: <strong>{{ analyticsSummary() }}</strong></p>
      </div>

      <p>
        *🔬 Попробуй изменить URL в браузере вручную, например: <code>/dashboard/101?search=reactive</code>.
        Компонент точечно обновит DOM без тотального ререндера класса.
      </p>
    </div>
  `
})
export class Day4Step1 {
  /**
   * 1. Входящие параметры URL автоматически оборачиваются в readonly-сигналы.
   * Имя свойства строго совпадает со строкой конфигурации в роутах или query-ключом.
   */
  public readonly id = input<string | undefined>();
  public readonly search = input<string | undefined>();

  /**
   * 2. Цепочка вычислений (DAG). Автоматически пересчитывается,
   * когда рантайм Angular обновляет входные сигналы id() или search().
   */
  public readonly analyticsSummary = computed(() => {
    console.log('🟢 [Dashboard Computed]: URL изменился, пересчитываю метрики...');
    const processId = this.id() ? `#${this.id()}` : 'Базовый';
    const query = this.search() ? `с фильтрацией по слову "${this.search()}"` : 'без фильтрации';
    return `Анализирую поток [${processId}] ${query}. Системные ноды стабильны.`;
  });

  constructor() {
    // Трассировка обновлений для лабораторного лога
    effect(() => {
      console.log(`📡 [Dashboard UI Effect]: DOM хирургически изменен. Текущий ID в памяти: ${this.id()}`);
    });
  }
}
```

### 🔬 Что этот опыт показывает Senior React разработчику?
1. Никаких хуков разметки: Больше не нужно писать `const { id } = useParams()` или работать со стейтами истории навигации. Параметры залетают в класс как обычные декларативные свойства.
2. Идеальный Lazy Loading: Angular автоматически разделит код и создаст отдельный асинхронный чанк (JS-файл) для DashboardComponent на этапе сборки. Код скачается браузером только в момент перехода на страницу `/dashboard`.

## Шаг 2: Реактивные мосты: Трансформация RxJS потоков в Signals (`toSignal`) (3 часа)
- Теория: Роутер и HTTP-клиент Angular исторически возвращают асинхронные потоки RxJS Observable. Но шаблоны в Zoneless-режиме хотят читать синхронные Signals. Изучаем функцию-мост `toSignal()`, которая подписывается на поток, управляет его жизненным циклом и конвертирует асинхронные события в синхронный стейт.
- Практика: Реализация поиска «на лету» с дебаунсом. Связываем input-сигнал поисковой строки, пропускаем его через RxJS операторы `debounceTime` и `switchMap` для отмены Race Conditions при запросах к API, и преобразуем результат в нативный `Signal` для хирургического вывода в DOM.

## Шаг 3: Функциональные Guards и Resolvers в Zoneless-окружении (2 часа)
- Теория: Полный отказ от старых ООП-классов CanActivate. Написание легковесных стрелочных функций-гвардов, которые проверяют статус авторизации во внешнем сторе или куках перед переходом. Изучение работы резолверов: как дождаться ответа от сервера до того, как компонент начнет инициализироваться.
- Практика: Написание гварда authGuard, который запрашивает статус ядра из нашего вчерашнего `ExternalEngineStore` (используя фабричный `inject`), и блокирует переход на страницу админки, если внешнее ядро находится в режиме Offline.

## 🧪 Лабораторный чек-лист конца дня (Что должно работать в браузере)
1. При вводе в URL `/dashboard?search=angular` компонент автоматически подхватывает строку поиска через сигнальный инпут.
2. Сетевые запросы не дублируются при быстром вводе благодаря RxJS-операторам, а UI не моргает, так как граф зависимостей обновляется синхронно.
3. Попытка перейти на секретный роут при выключенном внешнем движке перенаправляет пользователя на главную страницу песочницы.
