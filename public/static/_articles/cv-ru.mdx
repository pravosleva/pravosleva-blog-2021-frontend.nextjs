2025.01 - 2026.07 (1 год 7 месяцев)
### ✅ Результат для работодателя и заказчика по долгосрочным проектам, за которые я отвечаю
- Старт нового проекта (Личный Кабинет ДМС для крупного страховщика) в рамках существующей микрофронтовой архитектуры с соблюдением корпоративного код-стайла в рамках определенного стека технологий;
- Мой работодатель (подрядчик) на хорошем счету у заказчика - все задачи спринтов за 2025 год протестированы и сданы в срок, текущие проекты вызывают живой интерес и пролонгацию активностей со стороны бизнеса (на момент моего ухода проект перешёл в стадию поддержки и был передан заказчику);

### 🛠️ Задачи
- **Делаю из сложных вещей простые**, перед разработкой новой фичи формирую дерево задач для себя и коллег (когда это необходимо);
- Разработка и поддержка клиентской части веб-приложения (в т.ч. PWA и WebView для мобильного приложения); **Разрабатываем дизайнерский UI с уважением к UX, DX и потреблению ресурсов на устройстве пользователя**;
- **Код-ревью** других разработчиков (практикуем "защитное программирование", стремимся к чистому коду, пригодному для масштабирования и переиспользования); Имею опыт поддержки и развития проектов годами, проецирую его на текущие задачи, отмечу следующее 👉 мои подходы в решении задач бизнеса ориентированы на долгосрочные проекты (адаптация к обновлениям функциональных требований для нашей команды - не проблема в любой точке развития бизнеса); Пишу эффективный и отказоустойчивый JS-код пригодный для понимания, тестирования, отладки и переиспользования разработчиком любого уровня (это у нас основной критерий код-ревью);
- **Анализирую производительность, нахожу и устраняю проблемы** (Chrome Devtools - Performance), либо формулирую задачи соответствующим командам (в зависимости от зоны ответственности);
- Для автоматизации рутины использую bash скрипты (без фанатизма, но с ощутимой пользой);

### ⚙️ Стек
- **JavaScript ES6+ / TypeScript;**
- **React;**
- Для организации стейта: **Context API, Redux Toolkit, XState, кастомные "реактивные" решения;**
- MicroFrontends (Webpack Module Federation);
- Web API - в основном для работы с фреймами, воркерами, сторонними сервисами (к примеру, чат-сервисы Edna);
- Styled Components как основной вариант стилизации (но я не против использовать другие инструменты, например, **CSS modules**, популярные UI киты и т.д.), сам предпочитаю **Tailwind CSS;**
- Microfrontends, Next.js 15.x (Turbopack), Vite либо что-то еще по необходимости;
- PWA, работа в оффлайн режиме, настройки кэширования, использование Shared Worker, Dedicated Worker, Service Worker;
- Также на практически на ежедневной основе использую: PM2, NGINX, GIT, Strapi, Redux Toolkit, XState, Valtio, Material UI (MUI), Tailwind CSS, Vite, Vitest, работа с "деревьями" на чистом JS, Web Workers (Dedicated Worker, Shared Worker, Service Worker), Socket.IO, Web Push, IndexedDB, Telegram API, GraphQL, REST API, OpenAPI (Swagger);

### 🎓 Личные достижения (по убыванию приоритета/значимости)
- Написал **[реактивный опенсорс движок на чистом JS](https://www.npmjs.com/package/@pravosleva/reactive-engine) с возможностью адаптации к React 18+**, а также добавлена поддержка для Vue 3.2+ и для Angular 16+ (кое-где используется как легковесный стейт-менеджер, в том числе для отслеживания связей сложных состояний);
- **Практикую использование AI в работе** для повышения собственной эффективности (продуктивность повысилась в 4 раза, количество потенциальных багов, которые могут быть выявленны тестировщиками - стремится к нулю); Как следствие 👉 всегда демонстрирую высокий темп работы, без проблем беру на себя много задач, постоянно "пинговать" меня необходимости не наблюдается;
- Улучшил навык диагностики производительности продукта, есть практическая польза;
- **Новый опыт в микрофронтенд-архитектуре (Webpack Module Federation)**; Опыт переписывания легаси-функционала на "микрофронты";
- **Всегда под рукой ощущаемый прогноз релизов**, а также дорожная карта и анализ тренда эффективности моего отдела на основании закрытых задач за последние периоды: неделя, 1-3-6 месяцев (это позволяет получить более точный скорректированный прогноз по срокам предстоящих релизов больших задач);
- В свободное время (которого не так много) веду блог в котором собираю интересные нетривиальные решения на чистом JavaScript;
