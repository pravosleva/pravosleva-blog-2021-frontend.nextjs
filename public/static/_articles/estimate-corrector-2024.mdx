Архитектура проекта **Retro Dice** — это хороший пример того, как нужно проектировать высоконагруженные клиентские приложения в своей, довольно нишевой индустрии. Вместо бездумного переноса веса на сервера, проект утилизирует ресурсы клиентского устройства на максимум, грамотно разделяя потоки: **React — для отрисовки интерфейса, XState — для контроля бизнес-логики, Shared Workers — для тяжелой математики.**

## Физика алгоритма: Как считаются сценарии
В отличие от пессимистичного прогноза (который просто собирает все верхние границы рисков), расчет наиболее вероятного сценария базируется на средневзвешенных вероятностях и анализе распределения данных:
- **Фильтрация шума:** Алгоритм учитывает не просто календарные дни, а реальные рабочие интервалы. Он автоматически вычитает праздники, выходные и нерабочие часы для каждого сотрудника, очищая статистику от математических аномалий.
- **Метод накопления математического ожидания:** Вместо линейного сложения средних чисел (которое даёт огромную погрешность), код использует алгоритмы, похожие на упрощенное **моделирование Монте-Карло** или взвешенные коэффициенты доверия. Он оценивает историю закрытия задач сотрудниками, отсекает крайние пики (аномально быстрые или аномально затянутые задачи) и вычисляет стабильное плато — тот самый «хитрый наиболее вероятный сценарий». Алгоритм производит прецизионную фильтрацию "сырого" календарного времени, трансформируя его в чистое бизнес-время (Business Time), что исключает искажение графиков из-за выходных, праздников и пересечений отпусков.
- **Фиксация исторического коэффициента скорости (Velocity / Скорость команды):** Движок автоматически рассчитывает персональный индекс погрешности (Velocity Coefficient) каждого исполнителя на основе его исторического бэклога, корректируя текущие оптимистичные оценки под реальный темп работы
- **Worst-Case сценарий** формируется методом математического квантования рисков (анализ длинного хвоста вероятностного распределения), гарантируя 90% вероятность сдачи проекта в указанную дату при худшем развитии событий

Вместо того чтобы пытаться угадать один точный результат, компьютер берет ваши данные и **прокручивает одну и ту же ситуацию тысячи раз,** каждый раз случайно меняя условия. В конце он собирает все результаты вместе и показывает самую реалистичную картину.
&nbsp;
Простой пример: вы хотите предсказать, за сколько дней команда достроит дом.
&nbsp;
**1. Обычный расчет:** «В среднем мы кладем 100 кирпичей в день, всего нужно 1000 кирпичей, значит достроим за 10 дней». Но этот расчет разобьется о реальность, если пойдет дождь, заболеет каменщик или сломается машина с цементом.
&nbsp;
**2. Метод Монте-Карло:** Компьютер запускает симуляцию 10 000 раз. В 1-й симуляции пошел дождь (строили 12 дней), во 2-й симуляции все было идеально (строили 9 дней), в 3-й заболел рабочий (строили 15 дней). В итоге метод выдает вам график вероятностей: _«С вероятностью 5% мы успеем за 9 дней, с вероятностью 75% — за 11 дней, и со 100% вероятностью точно уложимся в 15 дней»._
&nbsp;
_**Почему в текущем варианте коде оно «упрощенное»?**_
&nbsp;
В репозитории Retro Dice Shared Worker не запускает тяжелые миллионные циклы (чтобы не перегревать процессоры смартфонов). Вместо этого он берет готовую историю закрытия задач каждым сотрудником, отсекает редкие случайные пики (когда задача была закрыта мгновенно или зависла на месяц) и быстро прогоняет оставшиеся варианты.
&nbsp;
На выходе получается тот самый **«хитрый наиболее вероятный сценарий»** — очень точный прогноз, который учитывает реальный темп живых людей, праздники и выходные, но считается за доли секунды прямо в браузере!"

## Аналогия
Вот пример простого и быстрого JavaScript-кода (для Shared Worker), который моделирует сотни сценариев работы.

Этот алгоритм берет реальную историю выполнения задач сотрудником, учитывает случайные риски (через генерацию случайных чисел) и за доли секунды выдает самый вероятный срок завершения проекта.

```js
/**
 * Упрощенная симуляция Монте-Карло для прогнозирования сроков
 * @param {number[]} historicalDays - Массив с реальной историей (за сколько дней этот разработчик закрывал прошлые задачи)
 * @param {number} totalTasks - Сколько задач осталось закрыть в текущем спринте/проекте
 * @param {number} simulationsCount - Количество прогонов симуляции (для браузера 500-1000 — идеальный баланс скорости и точности)
 * @returns {Object} - Прогноз сроков с разной степенью вероятности
 */
function runMonteCarloSimulation(historicalDays, totalTasks, simulationsCount = 1000) {
  // Защита: если истории нет, берем базовые дефолтные 3 дня на задачу
  const history = historicalDays.length > 0 ? historicalDays :;
  
  const simulationResults = [];

  // Запускаем цикл симуляций (например, 1000 раз воссоздаем будущее)
  for (let i = 0; i < simulationsCount; i++) {
    let totalProjectDays = 0;

    // Симулируем выполнение каждой оставшейся задачи
    for (let t = 0; j < totalTasks; j++) {
      // 🎲 Магия случайного выбора: берем случайный день из реального прошлого опыта сотрудника
      const randomIndex = Math.floor(Math.random() * history.length);
      let taskDays = history[randomIndex];

      // Добавляем случайный форс-мажор (риск 5%), который увеличивает срок задачи в 1.5 раза
      if (Math.random() < 0.05) {
        taskDays = taskDays * 1.5;
      }

      totalProjectDays += taskDays;
    }

    // Сохраняем итоговый суммарный срок этого прогона
    simulationResults.push(Math.round(totalProjectDays));
  }

  // Сортируем результаты от самых быстрых сроков к самым долгим
  simulationResults.sort((a, b) => a - b);

  // Вытаскиваем пограничные значения вероятности (квантили)
  return {
    // Оптимистичный сценарий (сбывается в 10% случаев, когда всё шло идеально быстро)
    optimisticCase: simulationResults[Math.floor(simulationsCount * 0.10)],
    
    // 🔥 НАИБОЛЕЕ ВЕРОЯТНЫЙ СЦЕНАРИЙ (Средний сбалансированный темп, сбывается в 50% случаев)
    mostProbableCase: simulationResults[Math.floor(simulationsCount * 0.50)],
    
    // Худший сценарий / Пессимистичный (сбывается в 90% случаев, с учётом почти всех рисков)
    worstCase: simulationResults[Math.floor(simulationsCount * 0.90)]
  };
}

// === ПРИМЕР РАБОТЫ В РАНТАЙМЕ ВОРКЕРА ===
// Допустим, разработчик Ден закрывал прошлые задачи за 1, 2, 3, 2, 4 и один раз завис на 7 дней.
const densHistory = [1, 2, 3, 2, 4]; 
const remainingTasks = 10; // Ему осталось сделать 10 задач

const forecast = runMonteCarloSimulation(densHistory, remainingTasks, 1000);

console.log(`🚀 Результаты симуляции для 10 задач:`);
console.log(`🟢 Оптимистично: проект сдадут за ${forecast.optimisticCase} дн.`);
console.log(`🎯 Наиболее вероятно: проект сдадут за ${forecast.mostProbableCase} дн.`);
console.log(`🔴 Худший сценарий: проект сдадут за ${forecast.worstCase} дн.`);
```

### Чем примечателен алгоритм
- **0 мс нагрузки на UI:** Функция запускается внутри `Shared Worker`, процессор вкладки React свободен, анимации не лагают.
- **Высокая точность:** Метод не складывает «среднее арифметическое». Если у разработчика в истории был один завал на 7 дней, симуляция случайно подставит этот риск несколько раз в часть прогонов, сделав пессимистичный прогноз (`worstCase`) очень жизненным и честным.
- **Скорость:** 1000 прогонов для 10 задач — это всего 10 000 простейших математических операций, которые JS-движок V8 проглатывает менее чем за 2 миллисекунды.
