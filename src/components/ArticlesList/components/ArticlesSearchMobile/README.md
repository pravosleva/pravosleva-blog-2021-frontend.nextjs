```ts
/**
 * ✅ BUGFIX: Явный публичный метод для изменения строки поиска.
 * Он вызывается только тогда, когда ПОЛЬЗОВАТЕЛЬ вводит текст в инпут.
 * Никакие внутренние тики дебаунса ресурса его не затриггерят.
 */
public changeQuery(newQuery: string): void {
  this.searchQuery.value = newQuery
  // Если мы ушли на дальние страницы, принудительно возвращаем пользователя на 1-ю
  if (this.currentPage.value !== 1) {
    this.resetPagination()
  }
}
```

## Почему это происходит (Механика бага)
Давайте пошагово проследим цепочку событий, когда пользователь вводит текст, а затем пытается нажать кнопку «Вперед» (перейти на страницу 2):
1. **Ввод текста:** Пользователь пишет в инпут слово "React".
2. **Срабатывает подписка:** Сигнал searchQuery меняется. Наша приватная подписка `resetPageSubscription` просыпается, видит, что currentPage.value === 1, условие `if (this.currentPage.value !== 1)` возвращает `false`, и сброс не происходит. Это штатное поведение.
3. **Запускается дебаунс:** Ресурс `searchResource` видит изменение строки, но благодаря `withDebounce(..., { delay: 400 })` он не отправляет запрос сразу, а взводит таймер на 400 миллисекунд.
4. Клик на пагинацию: Пользователь, не дожидаясь ответа (или уже получив первый ответ), нажимает кнопку «Вперед». Сигнал currentPage.value становится равен 2.
5. **Взрыв реактивности:** Изменение страницы мгновенно инвалидирует вычисляемое свойство `resourceDeps = [searchQuery.value, currentPage.value]`. Ресурс видит, что зависимости изменились, и повторно инициирует функцию фетчинга.
6. **Гонка тиков и баг:** Обертка `withDebounce` угадывает, что это новый виток асинхронной задачи. Внутри движка ReactiveEngine функция-обертка для дебаунса часто устроена так, что она передает текущие актуальные значения зависимостей или повторно аффектит сигналы (включая `searchQuery`), чтобы обновить контекст выполнения.Как только `withDebounce` в момент тика неявно обращается к `searchQuery` или обновляет его внутреннее состояние — наша подписка `resetPageSubscription` ошибочно думает, что строка поиска изменилась снова!
7. Откат назад: Подписка просыпается на шаге №6, видит, что `currentPage.value` сейчас равен `2`. Условие `2 !== 1` срабатывает, вызывается `this.resetPagination()`, и страница директивно сбрасывается обратно в `1`. Запрос на вторую страницу физически отменяется или подменяется первой.

## Как это исправить правильно?
Эту подписку нужно полностью удалить. Она здесь больше не нужна по двум причинам:
1. **Движок делает это сам:** В экосистеме `ReactiveEngine` управление сбросом зависимостей привязывается к ключевому триггеру. Если нам нужно, чтобы при изменении текста страница сбрасывалась в `1`, это делается либо в React-компоненте при вызове setQuery, либо в явном методе мутации.
2. **Безопасный метод `changeQuery`:** Вместо скрытой слежки через `.subscribe`, которая ловит внутренние тики дебаунса, мы сделаем чистый, явный публичный метод для изменения строки поиска.
