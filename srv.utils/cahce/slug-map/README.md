Если мы изучим исходный код `@pravosleva/reactive-engine` (метод `resource`), то увидим, как устроена архитектура этого пакета. Движок возвращает синхронное состояние, а сама асинхронная загрузка скрыта внутри реактивного замыкания. Геттер `.value` возвращает объект в виде:
```ts
{
  data: T | null;      // Сюда складывается результат вашего fetch-запроса
  isLoading: boolean;  // Флаг загрузки
  error: Error | null; // Сюда падает пойманная ошибка
}
```

Поскольку геттер выдаёт это состояние мгновенно (синхронно), `await` на него действительно не действует. Но при первой инициализации или когда TTL истекает, **движок в фоне запускает асинхронный процесс обновления**, временно выставляя `isLoading: true`.

В вашем коде в `switch(true)` вы пытались проверить `cacheValue.data`. Это было абсолютно верным решением! Ошибка в рантайме происходила из-за того, что при первом самом старте сервера (page load) кэш еще пуст, сетевой запрос в фоне только начался, и `cacheValue.data` равен `null`. Код проваливался в `default`, где `universalHttpClient.get` делал дублирующий запрос.
